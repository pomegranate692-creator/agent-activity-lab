# Shared runtime (read this before building a prototype)

Every prototype uses the same event model, the same scenario, and the same UI chrome so the ten concepts can be compared on identical activity.

```
shared/
  scenario.json / scenario.js   the shared SIMULATED task (generated by make_scenario.py; do not hand-edit)
  core.js                       AgentCore: reducer, Player, sources (simulated, jsonl, live SSE)
  chrome.js                     AgentChrome: header + source badge, inspector, controls, legend, capture hook
  theme.css                     mineral palette + shared UI styles
  adapter-server.mjs            static server + live event bus + Claude Code hook mapper
  test-hook-mapper.mjs          synthetic test for the hook mapper
```

## The scenario (simulated)

"Ship the v2.3 release notes". 12 agents, 67 events, 21.6 s at 1x. It contains parallel work (research and code), a handoff (plan to both), a blocker (the coder waits for approval), a failure (tests fail), recovery (approval granted, retry passes) and a final output (a draft release).
At t = 12.0 s every state is visible at once: 3 working, 4 done, 1 blocked, 1 failed, 3 waiting. The Paper boards show exactly that moment.

Agents: `orch` (Orchestrator), `plan`, `res` (+ `web`, `docs`, `diff` subagents), `code` (+ `lint`), `test`, `write`, `rev`, `ship`.

## Event model

All events: `{ t: ms, type, ... }`.

| type | fields |
|---|---|
| `task_started` | `task: {id,title,goal}` |
| `agent_spawned` | `agentId, name, label, role, parentId, dependsOn[]` |
| `work_delegated` | `fromId, toId, workId, description` |
| `tool_called` | `agentId, tool, input, durationMs, callId?` |
| `tool_returned` | `agentId, callId, durationMs, ok` (optional; sets the measured duration on the matching `tool_called`, adds no log line) |
| `message_sent` | `fromId, toId, text` |
| `agent_blocked` / `agent_unblocked` | `agentId, reason, needs` / `agentId, by` |
| `agent_failed` / `agent_retry` | `agentId, error` / `agentId, attempt` |
| `output_produced` | `agentId, outputId, name, kind` |
| `agent_completed` | `agentId` |
| `task_finished` | `status, outputIds[], summary` |

Agent states: `queued`, `waiting` (a dependency is not done), `working`, `blocked`, `failed`, `done`.

`AgentCore.applyEvent(state, ev)` turns events into a state object: `state.agents[id]` (with `state, tool, work, blockedReason, error, attempt, outputs, children, recent[]`), `state.delegations`, `state.dependencies`, `state.messages`, `state.outputs`, `state.log`, `state.counts`, `state.progress`, `state.source`.

## Source labels (the honesty rule)

`state.source` is one of `simulated`, `live-hook`, `transcript`, `self-reported`. The chrome shows it as a badge that a prototype cannot remove. Never write UI copy that implies scripted activity is real. If you add copy, say "simulated" where it applies.

## Building a prototype

1. Copy `prototypes/00-template` to `prototypes/NN-name`.
2. In `proto.js` call `AgentChrome.mount({ id, name, tagline, create(stage, ctx) { ... } })`.
3. Implement `update(state, events, dtSim)` (state changed), `frame(dtMs, nowMs, state)` (animation), `onSelect(id)`, `onReset(state)`, `resize(size)`.
4. Click/Enter on an agent must call `ctx.select(id)` so the shared inspector shows its current task and recent actions.
5. Respect `ctx.reducedMotion()`: no continuous or large motion when true; show state changes instantly.
6. Plain scripts only (no build step, no CDN). It must open from disk (`file://`) and from `node shared/adapter-server.mjs`.

## Running

```bash
node shared/adapter-server.mjs            # http://127.0.0.1:7777/prototypes/<name>/index.html
open prototypes/NN-name/index.html        # also works straight from disk
```

URL params: `?scenario=stress` (30 simulated agents, for scale checks), `?t=12000` start at a time, `?speed=2`, `?autoplay=0`, `?reduced=1`, `?live=http://127.0.0.1:7777`.
Keys: Space play/pause, R replay, 1-4 speed, arrows scrub, Esc deselect.

## Live adapter

```bash
node shared/adapter-server.mjs --port 7777
curl -X POST 'http://127.0.0.1:7777/sim?speed=2'          # play the SIMULATED scenario through the bus
curl -X POST http://127.0.0.1:7777/event -d '{...}'      # self-reported events (badge: SELF-REPORTED)
curl -X POST http://127.0.0.1:7777/claude-hook -d @payload.json   # Claude Code hook payloads (badge: LIVE · hook)
curl -X POST 'http://127.0.0.1:7777/replay?speed=4' -d @replay.json   # recorded transcript (badge: REPLAY · transcript)
open 'http://127.0.0.1:7777/prototypes/NN-name/index.html?live=http://127.0.0.1:7777'
```

### What is verified against real Claude Code (2.1.263), and what is not

| Path | Status |
|---|---|
| Hook payload fields `session_id`, `hook_event_name`, `prompt`, `reason`, `cwd` for SessionStart, UserPromptSubmit, SessionEnd | **Verified**: captured from a real run (`shared/fixtures/real-hook-payloads.jsonl`, test: `node shared/test-real-payloads.mjs`). This found and fixed three mapper bugs (lost task title, session-end reported as "succeeded", 14 s of dead clock). |
| PreToolUse / PostToolUse / PostToolUseFailure / PermissionRequest / Subagent* payloads (including pairing by `tool_use_id` for measured durations) | **Not verified**: the real run ended at an auth failure before any tool ran. Mapped from the documented shape (`node shared/test-hook-mapper.mjs`, synthetic). |
| Transcript replay (`tools/transcript-to-events.mjs`) | **Verified** on a real local transcript: 80 tool calls, 2 real tool errors and retries, replayed into prototypes 05, 07 and 09 with the REPLAY badge and no page errors. Transcripts do not record permission waits, messages or outputs, so those are never shown in a replay. |

To capture real hook payloads from a real session without touching your global settings (older route; the installer above is simpler) (needs a working `claude` login):

```bash
AGENT_HOOK_LOG=$PWD/live-test/raw.jsonl node shared/adapter-server.mjs --port 7791 &
claude -p "your task" --settings shared/claude-code-hooks.live-test.json --setting-sources project,local
```
`shared/claude-code-hooks.live-test.json` posts every hook to port 7791 and never blocks Claude Code. To watch every session you would merge its `hooks` block into `~/.claude/settings.json` yourself; I did not edit your settings.


### Connect real Claude Code activity (nothing is changed unless you run these)

```bash
node shared/adapter-server.mjs                       # 1. adapter; badge reads CONNECTED · WAITING until events arrive
node tools/hooks-install.mjs --log raw-hooks.jsonl   # 2. DRY RUN: shows the exact settings change, writes nothing
node tools/hooks-install.mjs --log raw-hooks.jsonl --apply   # 3. writes it (project scope by default; --scope user for every session; .bak made)
# 4. start a NEW Claude Code session and do some work, then:
open 'http://127.0.0.1:7777/app/index.html?live=http://127.0.0.1:7777'
node tools/hook-coverage.mjs raw-hooks.jsonl         # 5. which hook events and fields were really seen vs still assumed
node tools/hooks-install.mjs --remove --apply        # undo: removes only the entries this tool added
```
`tools/hook-forward.mjs` is the hook command. It prints nothing and always exits 0, so it cannot block, approve or alter anything in Claude Code, and it gives up after 1.5 s if the adapter is not running. `--log` keeps a local raw copy (prompts and tool inputs can be in there; it never leaves your machine). `hook-coverage.mjs --fixture out.jsonl` writes a redacted copy to commit as a regression fixture.

## Acceptance checklist for each prototype

- Runs from `prototypes/NN-name/index.html` with no build step.
- Shows: task and progress; main agents and subagents; delegation; dependencies (waiting); messages; tool use; working, waiting, blocked, failed (and retry), done; outputs as they appear; final result.
- Shared chrome controls work (play, pause, replay, speed, scrub) and the inspector works when an agent is clicked.
- Reduced motion handled. Keyboard: agents reachable and selectable without a mouse.
- Labels readable at 1280x800, no clipping, contrast checked.
- `previews/NN-name.mp4/.gif/.png` captured from the running prototype with an agent selected during the clip.
- `prototypes/NN-name/README.md`: what it shows, how it encodes each state, how to run, known limits, what you would change next.
